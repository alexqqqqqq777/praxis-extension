# Аудит приватності Praxis

Мета, задана замовником дослівно: *«ніхто і ніяк не має знати нічого про
користувача, немає логів — немає нічого; простий зрозумілий код для аудитора,
відкритість»*.

Юрист, який читає статтю закону, тим самим показує, над якою справою він
працює. Запит «ст. 625 ЦК, пошук „інфляційні за період окупації“» — це, по суті,
уривок правової позиції клієнта. Тому нижче все міряється одним питанням:
**що хтось сторонній може дізнатися про конкретного юриста і його справу.**

Дата аудиту: 15.09.2026. Обсяг: розширення (`manifest.json`, `src/*`),
сервер вітрини (`server/cards_api.py`), розгортання на VPS.

## B. Що лишається відкритим — за вагою

### B1. ~~Вітрина працює по HTTP~~ — закрито 15.09.2026 ✅

Було: `http://51.83.129.254:8788/cards?…&q=…` відкритим текстом. Провайдер юриста,
офісний Wi-Fi, будь-який вузол на шляху бачив і номер статті, і текст пошуку.

Стало: `https://praxis.51-83-129-254.sslip.io` — окремий піддомен, сертифікат
Let's Encrypt (автооновлення через `certbot.timer`, перевірено `--dry-run`),
nginx-термінатор окремим vhost.

Ключове в конфігурації термінатора — він **сам нічого не пише**:

```nginx
access_log off;
error_log  /dev/null crit;
proxy_set_header X-Real-IP "";        # IP користувача далі не передаємо
proxy_set_header X-Forwarded-For "";
```

Без цих рядків nginx повернув би рівно той журнал «хто яку статтю читав», який
ми прибрали з самого сервісу: сусідній `access.log` на цьому ж VPS важить 14 МБ.

Перевірено після живої сесії в браузері: у журналі сервісу — 0 записів про
запити, у журналах nginx — 0 згадок нашого vhost.

### B2. Сервер за побудовою бачить IP і статтю 🔴

Навіть без журналів оператор вітрини **може** їх увімкнути. «Ми не пишемо» — це
обіцянка, а не властивість системи. Повна відповідність меті досягається лише
архітектурно:

* **локально-перший режим** — підмножина корпусу по акту качається один раз
  (ЦКУ ≈ десятки МБ), далі все працює в браузері. Сервер бачить «хтось завантажив
  пакет ЦКУ», а не «о 14:28 читали ст. 625». Це єдиний варіант, де фраза
  «ніхто нічого не знає» правдива буквально;
* проміжний — качати блоками статей, а не по одній: сервер бачить «статті
  600–650», без точного попадання;
* решта (проксі, Tor) — перекладає довіру на іншого, не прибирає її.

Рішення за замовником; технічно готове до реалізації.

### B3. Текст пошуку `q` — найчутливіше поле 🟠

Номер статті ще можна вгадати. Слова, які юрист друкує в пошуку всередині
карток, — це вже формулювання його позиції. Варіанти: фільтрувати вже
завантажені картки в браузері (без мережі) або явно попереджати, що цей рядок
іде на сервер. Зараз — іде мовчки.

### B4. Порядок і час запитів 🟠

Навіть без записів той, хто слухає канал, бачить послідовність: ст. 625 → ст. 1212
→ ст. 267. Це впізнаваний профіль спору. Лікується тим самим B2 (пакети) і B1 (TLS
ховає шляхи, але не сам факт з'єднання).

### B5. Ключ доступу не має стати ідентифікатором 🟠

Зараз ключ **один спільний** — це правильно: користувачі між собою не
розрізняються. Щойно з'явиться «ключ на встановлення» — сервер отримає стійкий
ідентифікатор юриста, і мета скасовується. Зафіксувати як архітектурне
обмеження: ключ спільний або жодного.

### B6. `src/data.js` — вигадані номери справ 🔴 (не приватність, гірше)

Демо-набір містить **синтетичні посилання на неіснуючі постанови**. У правовому
продукті це небезпечніше за витік: юрист може процитувати вигадане. Зараз він
показується автоматично, коли бекенд не відповідає (`content.js:364`).
У публічній збірці демо-даних бути не повинно — замість них порожній стан
«вітрина недоступна».

### B7. Відкритість — це документи, а не лише репозиторій 🟠

Бракує: `LICENSE`, політики приватності (URL обов'язковий для Chrome Web Store),
обґрунтування кожного дозволу, опису загроз (цей файл — початок),
відтворюваної збірки, щоб аудитор зміг звірити опублікований CRX із тегом у git.
Репозиторій `alexqqqqqq777/Praxis` слід зробити публічним — інакше «відкритість»
непідтверджувана.

### B8. `host_permissions` публічної збірки 🟠

`http://127.0.0.1/*` і `http://localhost/*` у складі магазинної збірки означають
для рецензента «розширення ходить у локальну мережу» і будуть окремо
допитуватися. У релізі лишити тільки адресу вітрини; локальні — у
`optional_host_permissions` для розробки.

### B9. Chrome Web Store знає про встановлення 🟢 (неусувне)

Google бачить факт встановлення й оновлення. Прибрати неможливо — треба чесно
написати в політиці приватності, а не замовчувати.

### B10. Гігієна хоста 🟢

Додати `LimitCORE=0` (дамп пам'яті процесу містить щойно оброблені запити),
`PrivateTmp=true`. Резервні копії VPS не мають включати журнали інших сервісів
із нашим трафіком.

## C. Що перевірено і претензій немає

* **Жодної телеметрії, аналітики, лічильників.** Єдині мережеві виклики —
  вітрина, локальний `chrome.runtime.getURL('src/rail.css')` і відкриття ЄДРСР
  за явним кліком. Сторонніх доменів у коді немає.
* **`chrome.storage.local` зберігає три поля**: `open`, `theme`, `apiBase`.
  Ані історії переглядів, ані ідентифікатора, ані міток часу.
* **Дозволи мінімальні**: одне `storage`. Ні `tabs`, ні `history`, ні
  `webRequest`, ні `<all_urls>`.
* **Контент-скрипт живе на `zakon.rada.gov.ua/laws/show/*`** і читає лише DOM
  статті; у Shadow DOM, сторінку не змінює поза своєю панеллю.
* **Жодного віддаленого коду**: усі скрипти в пакеті, CSP забороняє інше.
* **`console.*` один раз** (`content.js:364`) і без даних користувача.
* **Розмір під аудит**: 2 355 рядків, з них мережевого шару — 38.
